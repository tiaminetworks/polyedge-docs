PolyEdge Detection API (27.0.0)

Download OpenAPI specification:

The Detection API provides poll-based HTTP access to PolyEdge's passive-radar output: the fused target position, persistent tracks, raw radar returns, model predictions, and drone Remote ID detections.

Each endpoint returns a section of a single message that the ISAC Engine produces once per coherent processing interval (CPI). GET /api/v1/latest returns the complete message; the narrower endpoints return individual sections of it. The WebSocket stream at ws://<host>:8765 carries the identical message, pushed as each CPI completes.

Positions are WGS-84. Latitude and longitude are decimal degrees, emitted with up to seven decimal places (approximately one centimetre); altitude is in metres and is not rounded. Angles are in degrees, ranges in metres, Doppler in hertz, and speeds in metres per second. Timestamps are ISO 8601 in UTC.

Detections and tracks

A detection is what a single CPI reports: a radar return, a model prediction, or a Remote ID broadcast, with no identity that carries from one CPI to the next. A track is a persistent estimate of one physical object, correlated across CPIs and assigned a track_id that is stable for the life of the track and is not reused within an ISAC Engine run. A track moves through tentative on creation, confirmed once it has been observed on several CPIs, coasting when a CPI produces no matching detection, and dropped when it has coasted past its timeout; a dropped track is reported once with state dropped and is then removed. GET /api/v1/tracks returns the current track set, and the same set is carried as the tracks array in GET /api/v1/latest. A client that needs to follow targets over time, derive their motion, or observe when one leaves coverage should consume tracks rather than raw detections.

Readiness

GET /api/v1/health reports whether the API process is reachable. GET /api/v1/stats reports whether detection data exists (data_status.has_data) and its age (data_status.last_update_age_seconds). GET /api/v1/latest returns 404 until the first CPI completes and 200 for every request thereafter, including on a CPI that resolved no target, in which case coordinate and the detection sections are null.

Poll rate

One message corresponds to one CPI. The CPI rate is deployment-dependent and is reported at runtime as radar.stats.update_rate_hz in GET /api/v1/latest. A request served more frequently than the CPI rate returns the message already retrieved; the ts and seq fields identify the CPI and allow a repeated message to be discarded.

History

Only the most recent message is retained. Responses carry no ETag or Cache-Control, and no endpoint returns an earlier message. seq increments by one per message within an ISAC Engine run, and run_id changes when the engine restarts, so a client can determine that a message was missed but cannot retrieve it. The WebSocket stream delivers every message and is the appropriate channel where message loss is unacceptable.

Rate limiting

The API enforces a per-client token-bucket limit, keyed by source address (the first X-Forwarded-For entry when the header is present). The default limit is 50 requests per second with a burst capacity of 100 and is configurable per deployment. A request that exceeds the limit receives 429 with a Retry-After header in seconds and an X-RateLimit-Limit header. GET / and GET /api/v1/health are exempt.

Authentication

The X-API-Key header is required only when the PolyEdge license carries an API_KEY value; otherwise all endpoints are unauthenticated. A missing or incorrect key receives 401. GET / and GET /api/v1/health never require the key.

Detections

The per-CPI detection message and its component sections. No identity carries between CPIs.

Full detection message

Returns the complete detection message for the most recent CPI: the fused coordinate, the persistent tracks, the raw radar returns, the model predictions, the drone Remote ID detections, the illuminator identity, and the derived geometry. This is the message that the WebSocket stream delivers.

The ts and seq fields identify the CPI. The message may contain properties beyond those listed here; schema_version changes only when a field is removed or renamed, not when one is added.

Fused target only

Returns the fused target coordinate, its source label, and its confidence, without the radar, model, or Remote ID sections. confidence is fusion.confidence, or null when fusion is absent. coordinate is null on a CPI that resolved no target.

Tracks

Persistent target tracks, each with a stable identifier and a lifecycle, correlated across CPIs.

Persistent tracks

Returns the persistent target tracks maintained across CPIs. Each track has a stable track_id, a lifecycle state (tentative, confirmed, coasting, dropped), a position, an ENU velocity, and per-axis quality values. A track that has ended is reported once with state set to dropped and is then removed from the list. seq increments by one per message within an ISAC Engine run; run_id changes when the engine restarts.

Request counters and data freshness

Returns request counters for this API process and the freshness of the detection data. data_status.has_data becomes true after the first CPI completes. data_status.last_update_age_seconds is the age of the most recent detection message; a value large relative to radar.stats.update_rate_hz indicates a stalled pipeline.

Liveness check

Reports whether the Detection API process is reachable, independent of whether the ISAC Engine is producing detections. Returns 200 while the process is running. Requires no API key.
